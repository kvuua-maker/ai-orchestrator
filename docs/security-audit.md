## Знайдено під час аудиту

**`artifacts` мав `FORCE ROW LEVEL SECURITY`, але не `ENABLE`.** У каталозі: `relforcerowsecurity=true`,
`relrowsecurity=false` — політики не діяли. Це та сама пастка, що й з `memory_chunks` на тижні 7;
тоді виправили одну таблицю, але не перевірили решту. Виправлено, додано регресійний тест
`apps/api/tests/rls-coverage.test.ts`, який вимагає `ENABLE + FORCE` для всіх 13 тенантних таблиць.

## Що захищено

- **Ізоляція даних** — RLS на 13 таблицях, політика на кожній, роль застосунку без `BYPASSRLS` і без `SUPERUSER`.
- **Аудит** — `audit_log` append-only: `UPDATE`/`DELETE` відкликані на рівні грантів, не на рівні коду.
- **Секрети** — у БД лише шифротекст (AES-256-GCM), у відповідях API — маска, в аудиті — без значення.
- **Репозиторій** — `.env`, `.secrets/`, ключі не відстежуються; скан коду не знайшов схожих на секрети рядків.
- **CORS** — білий список origin; чужий origin не отримує заголовків.
