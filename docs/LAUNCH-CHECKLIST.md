# Чек-ліст запуску

Що зробити, щоб підняти продукт на реальному сервері й віддати першому платному клієнту.
Кожен пункт — з конкретною командою або файлом, без «налаштувати інфраструктуру».

## 1. Сервер

- [ ] VPS: 4 vCPU / 8 ГБ RAM / 80 ГБ SSD (мінімум для 10–20 одночасних задач). Ubuntu 24.04.
- [ ] Docker + docker compose — `infra/docker/docker-compose.dev.yml` як основа.
- [ ] **gVisor** для пісочниці: встановити `runsc`, додати runtime у `/etc/docker/daemon.json`,
      зібрати `infra/docker/sandbox.Dockerfile` → `SANDBOX_DRIVER=docker`. Без цього ізоляція слабша.
- [ ] Домен + TLS (Caddy або nginx + certbot). Web на `:443`, API на `api.<домен>:443`.
- [ ] Фаєрвол: відкриті лише 22, 80, 443. Postgres/PgBouncer — **тільки localhost**.

## 2. База даних

- [ ] Postgres 16 + PgBouncer (`infra/pgbouncer/pgbouncer.ini`, `pool_mode=transaction`).
- [ ] `node scripts/db-bootstrap.mjs` — створює ролі `aio_owner` / `aio_app` / `aio_svc`,
      вмикає `ENABLE + FORCE RLS`, засіває плани.
- [ ] Перевірка: `node scripts/security-audit.mjs` → **20/20**.
- [ ] Бекапи: `pg_dump` щодня + WAL-архівування; перевірити відновлення на копії (не «налаштовано», а відновлено).
- [ ] Шифрування диска (LUKS або шифрований том провайдера).

## 3. Змінні середовища

| Змінна | Обов'язково | Примітка |
|---|---|---|
| `DATABASE_URL` | так | роль `aio_app`, через PgBouncer |
| `SERVICE_DATABASE_URL` | так | роль `aio_svc` (фонові задачі) |
| `VAULT_MASTER_KEY` | так | 32+ байти, генерувати `openssl rand -base64 48` |
| `ARTIFACT_SIGNING_KEY` | так | HMAC для підписаних URL |
| `DEEPSEEK_API_KEY` | так | LLM-планувальник |
| `WEB_ORIGIN` | так | `https://<домен>` — інакше CORS заблокує UI |
| `NEXT_PUBLIC_API_URL` | так | `https://api.<домен>` |
| `SANDBOX_DRIVER` | бажано | `docker` (з runsc) |
| `EMBEDDER` | ні | `fastembed` для реальної семантики, інакше hashing |
| `S3_*` | ні | зараз локальне сховище; S3 — коли потрібна георезервованість |

`chmod 600 .env`, власник — користувач сервісу. Ніколи не в git.

## 4. Безпека

- [ ] `security-audit.mjs` → 20/20 на продакшн-БД (не локальній).
- [ ] Ротація ключів: DeepSeek і GitHub-токен перевипущені (поточні засвітились у чаті).
- [ ] `WEB_ORIGIN` містить лише реальний домен (без `localhost`).
- [ ] Обмежити `/metrics` і `/v1/runs/reconcile?allTenants` на рівні проксі (внутрішня мережа).
- [ ] Логи не містять тіл запитів із секретами (перевірено: пишемо лише route/status/trace).
- [ ] Пентест або хоча б зовнішній сканер (ZAP baseline) — **не проводився**.

## 5. Моніторинг

- [ ] `GET /metrics` (Prometheus) → Grafana-дашборд: успішність, p95, квоти, 402, CORS-відмови.
- [ ] Алерти: успішність < 80% за 15 хв; p95 > 5 с; `stalled` > 0; помилки 5xx > 1%.
- [ ] `POST /v1/runs/reconcile` за cron кожні 5 хв (з `allTenants: true`).
- [ ] Логи → Loki/CloudWatch, збереження 30 днів.

## 6. Юридика й гроші

- [ ] Публічна оферта + політика конфіденційності (обробка персональних даних, GDPR-сумісність).
- [ ] Платіжний провайдер (Stripe / Paddle / LiqPay) + вебхуки → `invoices.status = paid`.
- [ ] Ціни зафіксовані в `plans` (free/pro/business), перевитрата — у `overage_per_1k_tokens`.
- [ ] Ліміти відповідають реальній економіці: перевірити собівартість 1 запуску (LLM + проксі) проти ціни плану.

## 7. Перший клієнт

- [ ] Онбординг пройдено на чистому акаунті (4 кроки, порожні стани, перша задача).
- [ ] Перевірити повний цикл: задача → handoff → відповідь → завершення.
- [ ] Перевірити квоту: вичерпати 100 запусків на тестовому тенанті → побачити 402 і зрозуміле повідомлення.
- [ ] Дати клієнту `trace-id` інструкцію: «назвіть його підтримці».
- [ ] Канал підтримки (email або Telegram) + SLA-очікування в листі.

## 8. Відкат

- [ ] Тег релізу в git; деплой — `git checkout <tag> && npm ci && npm run build`.
- [ ] Міграції БД — окремим кроком, з можливістю відкату (advisory lock + транзакція).
- [ ] План: якщо після деплою успішність < 50% — відкат на попередній тег і повідомлення клієнтам.

## Що НЕ перевірено — ризики, які треба закрити до першого платежу

1. **gVisor не запускався** — ізоляція пісочниці не підтверджена наживо.
2. **Реальна LLM-автономність** — 100% отримано на моках; із живою моделлю буде нижче.
3. **Пентест** — не проводився.
4. **Відновлення з бекапу** — процедура не відпрацьована.
5. **Платіжні вебхуки** — не підключені (інвойси створюються, але не оплачуються автоматично).
